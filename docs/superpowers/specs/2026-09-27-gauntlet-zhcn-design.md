# Gauntlet 简体中文设计

## 目标

为现有 `callmefree/acore-cloudbuild` 的 `mod-gauntlet` 构建提供完整的简体中文玩家体验：升级后三选一词缀、已携带词缀的动态说明，以及普通游玩中的聊天提示。只执行云编译与产物验证，不部署本地服务端。

## 现状

- `ci/modules.list` 已启用 `mod-gauntlet`，现有 Windows 兼容补丁必须保留。
- 客户端支持包 `GauntletUI/Data.lua` 已含 110 条中文词缀名和基础说明。
- `Panel.lua` 的 `ADESC` / `ODESC` 处理会用服务端英文动态说明覆盖中文基础说明。
- 上游 `mod-gauntlet` 的 `Describe()`、常规聊天提示和命令反馈仍是英文。

## 实现

1. 在云编译仓库维护一个独立的 `mod-gauntlet` 简体中文补丁，跟现有兼容补丁一起于克隆后应用；不修改上游仓库。
2. 玩家常见的词缀说明和聊天文本由服务端产生中文，保留动态数值、条件和词缀收益；协议标识、命令名、存档键及内部调试内容维持原样。
3. 客户端包保留已有中文词缀库；若需改动插件，使用独立文件并随云编译产物打包，避免只改本机客户端。
4. 运行模块可用的静态检查与测试，再触发 GitHub Actions Windows 构建，核对构建成功和产物包含汉化补丁。

## 风险与验证

- 上游 `master` 更新可能使补丁无法应用；工作流会明确失败，不会发布未汉化构建。
- 中文 UTF-8 必须在源码、补丁及最终客户端显示链路中保持完整。
- 云编译只能验证编译和打包；用户选择本次不进行本地部署或游戏内冒烟。
